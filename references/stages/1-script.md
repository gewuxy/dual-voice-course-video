# 阶段 1 · 写演讲稿（命令与格式）

产出 `$H/视频课/script_v2_dialog.txt`——驱动 HTML 帧结构与 TTS 的**唯一真相源**。

## 判断要点（认知铁律与介质改写）

- **角色分配铁律**：专业名词和术语只由老师说出，学生只答日常词；不确定的用「不知道！/猜不到！」再让老师揭示
- **视频介质改写**：用户原始内容若按线下课堂设计（分组讨论/上台演示/实物传递），须改写成视频可呈现的形式——线下执行的动作改成「看屏幕 + 听音频 + 回想 + 线上 HTML 游戏」等

## 格式（被 `verify_steps.py` 解析）

```
【第 1 帧】开场 · 主题
老师："请你仔细观察，它是什么颜色的？"[[1.2]]
学生："红色！"[[0.8]]
```

- 帧头 `【第 N 帧】`（`N` 前后允许空格）
- 角色行：老师固定 `老师：`，学生 `学生：`，台词用中文引号包裹
- `[[n]]` = 该句**之后**的静音秒数（学生思考 / 做动作的时间）
- 学生行含「哭脸 / 笑脸」→ 不念词，只留静音（做表情）
- 引号内不要出现 `"` `"`，否则解析器会漏句
- **一帧内的角色行数 = 该帧 HTML 的 `.step` 数**（阶段 4 能 1:1 对齐的唯一依据）

## 校验（阶段 1、2 各做完都跑一次）

```bash
python3 $SK/scripts/verify_steps.py "$H"
```

打印每帧 `.step` 数 vs 该帧台词句数，不一致即报错并 `exit 1`。step 数缺失会静默退化为帧内均匀分布（画面提前泄题），所以这一步不能跳。

提炼规则：

- 每课 **5 个左右**
